# 05 · 踩坑手册

## 一、数据源实况

### 1.1 各源能力对照

| 源 | 能拿到 | 拿不到 / 注意 |
|---|---|---|
| **Tushare Pro** | A股个股与指数日线（主力）；港股个股日线 `hk_daily`；国际指数 `index_global`（纳指 IXIC、标普 SPX、恒指 HSI）；财务数据（质地评分全靠它）；交易日历 | **接口按积分分档**，`hk_daily` 需较高积分；`index_global` **没有费城半导体 SOX、没有恒生科技 HSTECH**；分钟线需更高权限 |
| **券商 OpenAPI**（如老虎） | 港股个股、恒生科技、费城半导体、美股个股日线（**费半有 1994 年起的长历史**）；60分钟线；账户与持仓 | **美股实时行情需单独订阅权限**，没订阅时拿到的是隔日收盘价（见 1.3 的假同步事故）；需先在开放平台登记开发者、签协议、生成 RSA 密钥 |
| **AKShare** | 各市场兜底，费半可走新浪源 | 免费爬虫源，**无服务承诺**，格式和可用性随时可能变；仅作兜底不作主力 |
| **新浪财经 hq 接口** | 实时报价：A股 `sh/sz` 前缀、港股 `hk` 前缀、**美股/全球 `gb_` 前缀**（如 `gb_ixic` 纳指、`gb_nvda`） | 免费公开接口，无 SLA；格式固定但**各市场字段位次不同**（解析索引错位会取到 0） |
| **东方财富接口** | 实时报价 | **从阿里云服务器访问经常被断连**，不可靠，已弃用 |

### 1.2 最终路由（可直接抄）

```
A股个股/指数    日线 Tushare        → AKShare        实时 新浪 hq
港股个股        日线 Tushare hk_daily → 券商 → AKShare  实时 新浪 hk
恒生指数        日线 Tushare index_global → 券商        实时 新浪 hk
恒生科技        日线 券商（Tushare 不覆盖）→ AKShare     实时 新浪 hk
纳指/标普       日线 Tushare index_global → AKShare      实时 新浪 gb_
费城半导体      日线 券商（Tushare 不覆盖）→ AKShare      实时 新浪 gb_
```

### 1.3 事故：美股"假同步"

**现象**：A 股盘中点"同步行情"，美股三大指数全部显示 `0.00%`；后来又出现全部归零。

**根因**：券商账户没有美股实时行情权限，兜底逻辑落到"新浪日线收盘价"——
盘中拿到的是**隔日收盘价**，涨跌恒为 0.00%，是一次"假同步"；
且兜底解析处**没有有效性校验**，空值/零值直接覆盖了有效价。

**修法（三条永久规则）**：

1. 美股实时改用新浪全球实时接口 `gb_*`
2. **有效性闸门**：解析结果 ≤0、为空、或偏离最近日线收盘 >20% → 一律丢弃并保留上一有效值，界面标注"该源暂不可用"，**绝不显示 0**
3. 逐市场逐标的 try 隔离，单源失败不拖累整批

### 1.4 分钟数据的现实

1h/4h 图需要 60 分钟线。**免费源的分钟历史普遍很浅**（数周到数月），
所以：图上如实标注"数据起始"，不虚标；**按需加载**（打开该周期才拉 + 缓存增量），
禁止全标的常态分钟轮询（会撑爆限额）。

**铁律③**：分钟数据只供查看，规则引擎零引用，需有单测断言。

## 二、脏数据：最阴险的一类缺陷

### 事故：部分指数的周/月 K 切换失灵，全量历史消失

**现象**：一部分指数正常，一部分指数点周K/月K没反应、历史图不见了。

**排查歧路**：一开始怀疑数据源不同、代码分支不同，查了半天没结果。

**真根因**：行情表里混入了 **NaN**（某些源的原始数据带来：某指数 800+ 行无成交量、
个别行 OHLC 损坏）。拉全量历史时 **JSON 序列化崩 500**，周/月K 切换于是静默死掉；
日K 只取最近 250 根干净数据，所以没事 —— **"坏的共享同一缺陷"不是按数据源分，
而是按历史深度里有没有脏行分。**

**三层修法**：

1. SQL 一次性清洗存量 NaN
2. **入库护栏**：坏收盘整行丢弃，坏 OHLC/量置 NULL
3. **接口序列化兜底**：任何 NaN/Inf 转 null，不让它有机会崩

**方法论启示**：遇到"部分好部分坏"，先做**全量自查表**（每个标的逐项列出：
数据源 / 最早日期 / 行数 / 接口状态 / 控制台报错），规律会自己现形。
不要凭猜测修单个案例。

## 三、部署与环境

### 3.1 事故：代码改了但线上跑旧代码

修复后同步了文件却**没重建容器**，线上一直跑旧 bundle。
AI 的截图（本地新代码）和用户看到的（线上旧代码）都是真的，但结论错了。

**防法**：
- 固定流程：`改 → 同步 → 重建容器 → 线上取证`
- 页面显示**构建时间戳**（侧栏底部）
- 页面文档加 `no-store` 头，避免浏览器缓存造成的假故障

### 3.2 服务器规格

- **2 核 2G 跑不动**：Postgres + Redis + FastAPI + Next.js 构建会 OOM，构建阶段直接失败
- **最低 2 核 4G**，另加 2G swap（写进 fstab，重启保留）
- 磁盘 40G 起（全量历史 K 线 + 日志 + 备份）

### 3.3 端口与证书

服务器上已有服务占 80 端口时的三个选项：

- **A**（推荐，需备案域名）：Nginx 统一接管 80/443，按域名分流
- **B**：只监听 443，证书用 DNS-01 验证
- **C**（最快）：非标端口（如 8443）+ 自签证书，浏览器首次点"继续访问"信任一次

个人自用直接选 C，等有备案域名再切 A（Nginx 配置预留切换注释）。

### 3.4 部署脚本的坑

`rsync --delete` 会删掉服务器上不在本地的目录 —— 曾把证据目录整个删掉。

**永久排除**：`.env`、`secrets/`、`evidence/`、`logs/`、备份目录。

## 四、图表与画线（本项目最大的坑区）

### 4.1 选型：必须选支持交互画线的库

TradingView Lightweight Charts **不带交互画线工具**（只能程序画静态线）。
选它等于后期返工。**用 KLineCharts**（开源、画线套件齐全、画线对象可序列化入库）。

### 4.2 事故：对数坐标下拖动画线会变形（修了三次）

**根因**：库在 `mousemove` 每一帧按"等值价格差平移"渲染 —— 线性坐标没问题，
对数坐标下两端点移动的屏幕距离不等，线被拉伸。
前两次修复只作用在 `mouseup` 落库那一刻，**预览路径漏修**。

**正解**：所有画线 overlay 一律 lock（禁用库的内置拖动），
自建拖动层，`press → move（每帧）→ release` **三段共用同一个像素空间平移函数**。
在对数坐标下，像素平移等价于两端点价格**同乘一个比例**，形状恒定。

**验证标准**：录屏 + 拖动期间每 100ms 采样两锚点价格比值，全程恒定（误差 < 1e-6）。
**只验终点不算数。**

### 4.3 事故：锁定库拖动后，所有线都点不中了（手术成功病人没醒）

`onDragUp` 在计算最终锚点之前就清空了拖动会话引用，release 帧读到空会话直接放弃落库 ——
表现为"预览正常、松手回弹"。

**教训**：图表模块牵一发动全身，必须建**全功能矩阵**（G-0），每次改动全跑。

### 4.4 陡峭线段点不中

近乎垂直的线段在屏幕上只有 1–2 像素宽，按"到线体垂直距离 8px"判定几乎永远点不中。

**修法**：命中判定改"点到线段最短距离"，容差 12px；
近垂直线段额外启用**包围盒热区**（以线段为轴左右各 12px）；
端点手柄命中圈 14px 且优先级最高（陡线至少永远能靠端点选中）。

### 4.5 画线延伸被截断

确认写入时如果把画线重建为"按数据范围渲染的价位线"，线就会被剪到最后一根 K 线。

**几何铁律**：确认只改变身份和样式，**绝不改变几何**。
配套：图表右侧默认保留 30 根 K 线的**未来空白区**，否则延伸线"伸"不出去也看不见。

### 4.6 KLineCharts 的两个具体陷阱

- 指标线样式**必须给全字段**（缺 `dashedValue` 会在库内部 draw 时崩）
- `priceLine` 不带 timestamp 锚点时，点选命中检测会失效；
  单击容易被判成一次"按住拖动"循环导致选中态闪灭 —— 自建 DOM 层命中检测（6–12px 容差）更稳

### 4.7 跨周期与残留

- 画线锚点必须存 **(时间戳, 价格)**，不能存屏幕坐标或索引，否则切周期就错位
- **切换标的时必须全量重置覆盖层**，并对价位线渲染做归属 ID 校验 ——
  否则会出现"A 股票的标注画在 B 股票图上"（异步返回 + ref 未清导致）

## 五、规则引擎的坑

### 5.1 扫描窗口必须与数据深度解耦

灌入全量历史后，颈线会在十年前的某天被"扫到"，激活日全错。

**护栏**：结构激活/峰值的扫描起点 = **价位版本生效日**，与 K 线回填深度完全解耦。
全量历史只用于查看。

### 5.2 展示口径必须跟着状态走（"过期地图"病）

同一个病在原系统犯了三次：

- 结构已衰竭，卡片还显示"完成度 29.5%"
- 待激活的轮次，规则表还显示"未触发"（暗示"还在等着触发"）
- 用户标签为左侧，态势行仍显示"完成 37%·等 70% 档"

**正解**：展示口径按状态切三种，全站统一：

| 状态 | 口径 | 措辞 |
|---|---|---|
| 进行中 + 活跃 | **监控态** | "监控中 / 已触发@日期@价格" |
| 轮次已结束 | **回顾态** | "已执行@…" / "**已越过·未执行**" / "未到达（该轮峰值 x%）" |
| 待激活 / 待选型 | **休眠态** | 整表灰显 + "突破并入场后启用"，不显示触发状态列 |

**"未触发"三个字只允许出现在监控态。**

### 5.3 唯一约束撞车 = 神秘的"时灵时不灵"

哨兵设置"当天第一次必成功、重设必报 500" —— 根因是留痕信号表上
`(标的, 日期, 类型)` 唯一约束，同日第二次写入直接撞索引并回滚。

**修法**：手工留痕信号统一走 upsert（ON CONFLICT DO UPDATE）。
**启示**：任何"时灵时不灵"，先怀疑唯一约束和幂等。

### 5.4 信号与待办的同源去重

同一事件既有"信号"又有"待办"时，去重标记只对未处理待办生效的话，
用户处理完待办后，信号会失去遮蔽**以红卡复活**，紧挨着自己的灰色"已处理"副本。

**修法**：covered 标记由 `[...未处理, ...已处理]` 统一预标记。

## 六、通知（飞书）

- 自定义机器人有两种安全设置：**自定义关键词**（简单，推荐）与**签名校验**（要实现签名算法）
- 选关键词的话，**每条推送文本必须包含该关键词**，否则飞书**静默拒收**（不报错，最难查）
- 关键词做成配置项并在设置页标注"不可删"
- Webhook 地址等于"往你群里发消息的钥匙"，只放 `.env`，别贴到任何公开地方
- 自定义机器人**发不了图片**，日报里用字符进度条（`▓▓▓▓▓░░░ 88%`）代替图表；
  要真图表得走企业自建应用

## 七、市场时钟与盘中

### 7.1 三市场时钟

必须实现分市场交易时段日历（含 **A 股午休**、**美股夏令时/冬令时切换**、周末、
**美股凌晨段归属前一交易日**）。

**只请求开市中的市场**；休市市场保留最后有效价，徽章显示"已收盘"而非"盘中"，
涨跌幅显示该市场最后交易日的真实涨跌 —— 否则会出现"休市却挂着盘中 +0.00%"的误导。

### 7.2 盘中价必须持久化

只写内存/前端状态的话，**刷新就回退到昨收**，用户会以为功能坏了。

**正解**：同步结果服务端持久化（含时间戳与来源），页面加载一律
"收盘价 + 最新盘中快照"合并展示，显示时间戳最新者；16:30 正式收盘入库后自动取代当日快照。

### 7.3 防火墙

盘中价**只服务展示**，规则引擎/日报零接触，需有单测断言。
否则盘中一个插针就能骗响你的假突破警报。

## 八、系统时间与调度

- 时区统一 `Asia/Shanghai`
- **NTP 必须正常**：16:30 调度、哨兵日期、快照时间戳全押在系统时钟上
- 容器时区与宿主机时区要一致（容易漏）
- 交易日历用 Tushare，别用"周一到周五"硬判

## 九、备份与数据安全

### 事故：备份从未存在

部署方案里写了"每日 02:00 pg_dump"，但**从未实装** —— 没有脚本、没有 cron、
没有任何产物。等到误删数据时才发现无药可救。

**规矩**：

1. 备份是**阶段 2 的验收项**，不是"以后再说"
2. 必须**演示一次真实恢复到临时库**才算数
3. 设置页显示"最近备份时间 + 大小 + 表行数校验"
4. 每日全量 dump（保留 7 天）+ WAL 归档（可回滚到任意时点）
5. 在核心表装**数据库触发器**物理拦截未授权 DELETE

### API 日志落盘

容器一重建日志就没了，事后无法追溯（曾有连续 6 次 500 却查无对证）。

**正解**：结构化访问日志 + 异常 traceback 持久化（挂载卷，保留 30 天）；
前端 5xx 报错时显示**错误编号**，用户把编号一发就能直接翻出完整堆栈。

## 十、AI 协作中的具体坑（补充 03 册）

| 坑 | 表现 | 防法 |
|---|---|---|
| 单测"假绿" | 测试文件不在生产镜像里，靠手工拷贝，容器一重建全挂 | 自查脚本每次自动注入测试文件 |
| 夹具污染真实数据 | 自动化测试的弹窗 accept 竞态误写真实标的价位 | 沙箱标的 + 夹具全程 dismiss |
| 沙箱之间互相污染 | 一号沙箱残留历史信号，干扰新演示 | 演示用干净的新沙箱，**不要为了清理去硬删** |
| 权限确认全关 | 图省事开 `--dangerously-skip-permissions`，误删无人拦截 | 白名单常用操作，删除/外发消息仍需确认 |
| 会话中断丢上下文 | 网络断连、上下文超限 | 台账 + 回归清单在仓库里，新会话读文件接上 |
| 长会话越来越慢/易断 | 上下文过长 | 大批次交付后主动开新会话，用台账接续 |
