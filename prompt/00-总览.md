# 仓位管家 · 复刻工程包 · 总览

## 这是什么

一套面向**个人投资者**的「仓位管理 + 择时提示」Web 系统的完整复刻资料。

它不是量化交易系统，不自动下单，不预测行情。它的定位是：

> **你用经典技术分析看图、画线、做判断；系统把你的判断结构化保存下来，
> 每天收盘后用真实行情跟你的线做数学比较，到点提醒你，并记录全过程。**

一句话概括产品哲学：**判断归人，计算归机器，纪律归系统。**

---

## 这套资料适合谁

- 有自己一套技术分析方法，想把它固化成每日自动盯盘工具的个人投资者
- 手上有 AI 编程助手（Claude Code / Cursor / Codex 等），愿意花几天时间做产品负责人的人
- 能接受"先能用、再好用"的迭代节奏，而不是期待一次成型

**不适合**：想要开箱即用软件的人；想要自动交易系统的人；不打算自己做判断、只想要买卖信号的人。

## 三个必须提前接受的现实

### 1. 做不到"一模一样"，能做到"功能等价"

同样的蓝图交给不同的模型、不同的时间，生成的代码结构、类名、界面细节一定不同。本资料保证的是：**规则一致、数据模型一致、行为一致**。不要拿两套系统逐像素对比。

### 2. 这个包里少一个人 —— 你必须补上

原系统能收敛到可用状态，靠的不只是提示词，而是全程有人在做这四件事：

- **产品定义**：把模糊的"我要科学的减仓"翻译成"完成度 70% 减到剩 70%"这种可执行规则
- **亲自验收**：每次交付都自己打开页面点一遍，而不是相信 AI 的"已完成"
- **描述缺陷**：说"拖动过程中线在变形"而不是"画线有问题"
- **拒绝返工**：同一个坑掉第二次时，立刻要求把它写成永久回归项

**如果没人做这四件事，这套资料只能产出一个"看起来能跑、细节全是坑"的系统。**
03 号文档就是教你怎么做这四件事的。

### 3. 前三分之一的时间在建规矩，不在写功能

原系统最贵的教训：同一个画线缺陷修了三次都没修住，最后发现每次"验证通过"的证据都是假的（本地验证、终点校验、漏测线型）。
**先建台账和回归清单，再写功能**——这不是洁癖，是省时间。详见 03。

## 系统最终形态速览

**每天你只做两件事**：收盘后看一眼推送的日报卡片；有信号时打开看板处理。

**六个页面**

1. **看板**：指数基准带 → 哨兵热度卡 → 操作提示栏 → 全部标的态势列表
2. **标的库**：分组页签、批量导入、方向筛选
3. **突破确立**：谁刚起跑（已共振 / 待共振两段）
4. **头部确立**：顶部观察中 / 已确立（自带看顶准确率档案）
5. **账户**：持仓录入、模拟战役总账
6. **设置**：全部规则参数、运维、备份状态

**一只股票在系统里的一生**

```
你画两条线（颈线 + 量度目标）
        ↓
系统每天收盘拿真实价格跟这两条线比
        ↓
站上颈线 + 主指数右侧 → 入场提示（指数晚期只给半仓）
        ↓
完成度 70% / 80% / 90% → 三档减仓提示
        ↓
自峰值回撤 20% → 剩余全清提示
   或 你看出头部 → 画头部颈线 → 确认清仓
        ↓
结构走完 → 归档，等你的下一轮判断
```

全过程系统只提示、只记录，**不替你按下任何一次扳机**。
