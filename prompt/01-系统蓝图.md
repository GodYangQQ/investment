## 一、五条铁律（任何实现不得违反）

这五条是整个系统的宪法，写在所有提示词的开头，每轮交付都要复查。

| # | 铁律 | 含义 |
|---|---|---|
| **①** | **行情判断永远由人做** | 系统只做数学比较与查表。禁止任何"AI 判断形态/预测走势"的功能。形态成立、头部确立、方向标签，全部人工。 |
| **②** | **价位必经界面确认才入库** | 无论来源是手工输入、图上画线还是截图识别，都只产生"候选"，用户点确认才写库。任何绕过确认的写入都是缺陷。 |
| **③** | **信号只用日线收盘价** | 规则引擎不接触任何盘中/分钟数据。盘中价仅供展示，物理隔离（只写缓存层，规则引擎零引用，需有单测断言）。 |
| **④** | **质地评分只影响排序展示** | 基本面评分不得进入任何信号判定路径。 |
| **⑤** | **不接任何交易接口** | 不下单。执行层只定义接口与 Mock，为未来预留。 |

## 二、领域模型

### 2.1 标的（Instrument）

系统的基本单位。指数、个股、ETF 共用一张表，用 `type` 区分。

关键字段：

```
id, code, name
type            index / stock / etf
market          A / HK / US
sector          板块领域（自动或手动）
groups[]        用户自定义分组（多归属，标签制）
star            0-3 手动星标
quality_grade   A-D 自动质地档
direction_label 用户方向标签：right / base / left / undecided  ← 最高优先级
pool            持有 / 就绪 / 回撤关注 / 观察 / 归档
sub_status      等待突破 / 突破失败·等待重新站上 / 深蹲·候形态 / 已到目标·留仓 …
option_note     期权/融资备注（入场提示时带上）
```

**指数不进池子**：指数是基准层，在看板顶部独立展示，不参与池子分类。

### 2.2 关联指数（Instrument ↔ Index）

每个个股/ETF 可绑定多个指数，其中**必须有且仅有一个主指数**。

- **主指数**决定入场闸门（是否放行、是否半仓）
- 副指数仅作展示参考

### 2.3 结构与轮次（Structure Round）

**一组「颈线 + 量度目标」= 一轮结构**。同一标的可以有多轮，旧轮归档保留。

结构生命周期（纯数学，收盘价判定，**与是否持仓无关**）：

```
待突破  ──首个收盘 > 颈线──→  进行中  ──峰值完成度 ≥90%──→  已兑现
                                                              │
                                              距结构峰值回撤 ≥15%
                                                              ↓
                                                           已衰竭（终态，不因反弹回退）
```

- **完成度** = (现价 − 颈线) / (目标 − 颈线)
- **结构峰值** = 激活后的最高收盘价
- 衰竭后：完成度停止以进行时口径展示，改为回顾式（"第一轮已兑现 x%·峰值 y·现距峰值 −z%"）

### 2.4 价位（Price Level）

带版本、带确认、带留痕。

```
level_type    neckline 颈线 / measured_target 量度目标 / second_target 第二目标
              / pre_breakout 预备突破位 / pullback_zone 回撤买入区（上下沿）
              / top_neckline 头部颈线 / reference 仅参考线
price, price_lower（区间用）
zone_mode     buyback 到位买回 / pattern 到位找形态   ← 回撤区专用
buyback_ratio 买回成数
version, status(active/superseded), superseded_by_id
source        manual / drawing / vision / system
confirmed_at  非空才生效  ← 铁律②
round_no      属于第几轮结构
note
```

**幂等规则**：与现行版本完全一致的保存不生成新版本（否则版本历史会被无意义的重复保存淹没）。

**失效线不落库**：= 颈线 × 0.95，由参数实时计算，颈线改版自动跟随。

### 2.5 画线（Drawing）

图上画的线，与价位是两个概念：**画线是图形，确认后才"提拔"为价位**。

```
tool_type     horizontal_line 水平直线 / horizontal_ray 水平射线
              / segment 线段 / ray 斜射线 / measured_move 量度工具
anchors[]     [(timestamp, price), ...]  ← 时间价格锚点，保证跨周期正确
style         color / width / dashed     ← 外观独立，改外观永不产生价位版本
semantic      null=草稿参考线 / 已提拔的语义类型
confirmed_level_id  提拔后关联的价位 id
```

**两段式交互**（重要）：

1. 画线 → 默认是**草稿参考线**（灰虚线），不弹窗、不入价位库，可随便画
2. 点选线 → 浮出工具条（颜色 / 线宽 / 线型 / 删除 / **确定**）
3. 只有点「确定」才读出价格 → 弹语义卡 → 确认写入 → 成为正式价位

**几何铁律**：确认写入只改变身份和样式，**绝不改变几何**（不截断、不缩短、不重画锚点）。

### 2.6 方向标签（Direction Label）· 战略层

四态，**由用户手工设定，压制系统的一切自动判断**：

| 标签 | 含义 | 视觉 | 系统行为 |
|---|---|---|---|
| **右侧** 📈 | 结构进行中，价格在有效结构上运行 | 红底徽章 | 完整右侧语言：完成度、阶梯、止盈全部激活 |
| **筑底** ⏳ | 已进入起涨区/平台，等形态 | **琥珀金 + 金边呼吸光** | 只盯形态，不谈买入 |
| **左侧** 📉 | 结构衰竭后回落途中 | 绿底 + **整卡降饱和静音** | 规则全部休眠，只显示"距起涨区还有多远" |
| **未定** | 未表态 | 灰 | 不参与红绿统计 |

**关键设计（这是最容易做错的地方）**：

标签必须**同时压制展示层和规则层**。标签为左侧/筑底时：

- 展示层：抹掉完成度、距目标、剧本收益、模拟收益、下一档提示；换成左侧语言
- 规则层：静默消费 K 线（只推进日期），不产生入场/减仓/止盈/假突破任何信号

系统自己算出的方向降级为「系统观点」，只出现在徽章悬停和详情页小字，**永不改变展示与规则**。

**自动流转（唯一的例外，且是纯数学）**：收盘进入用户自己划的回撤区/起涨区，或触及任一哨兵 → 自动转筑底 + 推提示。因为这一步不含任何行情判断。设置页可关。

### 2.7 池子（Pool）· 战术层

```
观察池  → 就绪池 → 持有池 → 回撤关注池 → 归档
```

- 与方向标签正交：标签是"山的哪一边"，池子是"手上什么状态"
- 流转由信号自动触发或手动迁池（不再依赖用户回填）

### 2.8 哨兵（Sentinel）· 反转预警

用户在关键位埋的"地雷"，**只提醒，永不自动改标签**。

```
price, direction（向上站上 / 向下到达）
source_ref      引用来源（起涨区上沿/颈线/前高/失效线）
每标的 ≤2 条
```

- 距离 ≤5% 进日报第 2/3 档，≤3% 触发关键事件加推
- 收盘穿越 → P2 提醒 + 待办"是否更新标签"
- **图上必须可见**：蓝色点划线 + `⚓哨兵 {价} {↑/↓}` 标签 + 右侧价格轴徽章 + 可拖动改价

### 2.9 战役与模拟收益（Campaign）

**系统只记模拟账，不记真实账**（这是重要的产品决策，见 02 册）。

- **模拟收益**：假定该轮全部信号按规则执行（满仓入 → 各档按比例减 → 止盈/清仓全清），用历史收盘价算整轮收益率
- 一轮可含多段（中途假突破清仓再入场 → 分段 1-1 / 1-2，整轮收益为各段复合）
- **剧本收益（前瞻）**：已录颈线+目标的标的，自动算"按剧本走完全程约 +x%"
- 全部为价格口径，可配杠杆系数

## 三、技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python + FastAPI | 与数据源生态（Tushare/AKShare）同语言 |
| 调度 | APScheduler | 单机够用，无需 Celery |
| 前端 | Next.js + TypeScript + Tailwind + shadcn/ui | AI 生成质量最高的组合 |
| **图表** | **KLineCharts** | **必须支持交互画线**（TradingView Lightweight Charts 不支持画线，选错会返工） |
| 数据库 | PostgreSQL | 版本留痕、JSON 字段、触发器（防硬删） |
| 缓存 | Redis | 盘中价、指数状态快照 |
| 部署 | Docker Compose + Nginx | 四容器：postgres / redis / api / web |
| 通知 | 飞书自定义机器人 Webhook | 免费、交互卡片、易接 |

## 五、数据源与路由

详细踩坑见 05 册。终态路由：

| 市场 / 品种 | 日线主源 | 日线备源 | 实时（盘中） |
|---|---|---|---|
| A 股个股与指数 | Tushare | AKShare | 新浪 hq |
| 港股个股 | Tushare `hk_daily` | Tiger → AKShare | 新浪 hk |
| 恒生指数 | Tushare `index_global` | Tiger | 新浪 hk |
| 恒生科技 | Tiger | AKShare | 新浪 hk |
| 纳指 / 标普 | Tushare `index_global` | AKShare | 新浪全球 `gb_ixic` 等 |
| 费城半导体 | Tiger | AKShare（新浪源） | 新浪全球 |

**通用要求**：

- 每根 K 线带 `source` 标记，源切换写日志
- **有效性闸门（永久规则）**：解析结果 ≤0、为空、或偏离最近收盘 >20% 一律丢弃并保留上一有效值，界面标注"该源暂不可用"，**绝不显示 0**
- 单市场失败不影响其他市场（逐市场 try 隔离）
- **全量历史**：个股自上市日、指数自发布日；取不到就取最早可得，图上标注"数据起始 YYYY-MM"

## 六、规则引擎

### 6.1 设计要求

**引擎必须是纯函数**：`evaluate(instrument, trade_date, db_snapshot) → [Signal]`，不依赖当前时间。

这一条带来两个红利：历史回放天然可用（拿过去的日线逐日喂进去就能验证规则）；单测好写。

### 6.2 评估顺序（同一标的同一天）

```
0. 方向标签压制闸门（左侧/筑底 → 静默，只推进日期）
1. 假突破清仓            P1
2. 头部颈线跌破          P1
3. 移动止盈全清          P1
4. 分段减仓（70/80/90）  P2
5. 到目标终减            P2
6. 共振入场 / 等待指数   P3
7. 回撤买回 / 买点作废   P3
8. 左侧→筑底自动流转     P4
9. 筑底完成候选提示      P4
10. 哨兵距离与穿越       P2/P4
```

### 6.3 去抖

去抖 key = `(标的, 规则, 池子+子状态, 价位版本)`。价位改版或状态迁移即允许再次触发。

### 6.4 历史回放

必备功能，也是验收手段：给定标的 + 年份，逐日重演，输出事件序列（日期 / 收盘 / 事件 / 动作）。

**回放的关键护栏**：结构激活/峰值的扫描起点 = 价位版本生效日，**与 K 线回填深度完全解耦**。否则灌入全量历史后，颈线会在十年前的某天被"扫到"，激活日全错。

## 七、页面与信息架构

### 7.1 全局框架

- **左侧 240px 固定导航**：看板 / 标的 / 突破确立 / 头部确立 / 账户 / 设置，底部显示最近行情时间 + 构建时间戳
- `<1280px` 收窄为 64px 图标栏；移动端转底部标签栏
- **全站满屏无居中窄栏**，浅色主题

### 7.2 看板（首页）· 自上而下

```
① 大结构统计条    右侧 n · 筑底 n · 左侧 n · 未定 n（点击即筛选）+ 各方向标的名
② 指数基准带      每指数一张胶囊：现价 / 涨跌 / 方向徽章 / sparkline / 完成度
③ 哨兵热度面板    三层折叠：贴脸(≤5%) / 临近(5~15%) / 安静(>15%)
                  同一标的合并为一张卡，卡内多条哨兵按距离升序
                  距离热度渐变：≤1% 深红 → 5% 橙 → 10% 黄 → ≥15% 绿
                  筑底标的加金色呼吸边
④ 操作提示栏      有信号才出现，否则一行"今日无操作提示·系统盯盘中"
                  卡类型：突破 / 回踩到位 / 筑底确认 / 头部确立 / 清仓警报 / 哨兵临近
                  优先级配色：P1 红+光晕脉冲 → 突破红 → 减仓橙 → 筑底金 → 哨兵蓝
                  已处理当日置灰沉底，次日消失
⑤ 态势列表        大型纵向可滚动列表 = 页面主体
                  每行：方向徽章 | 名称代码 | 现价涨跌 | 进度条 | 在等什么
                        | 轮次数字徽章①②③ | 质地环 | 板块 | 剧本收益
                  进度条三型：进行中=完成度条 / 候买回候形态=向下距离条 / 候突破=向上距离条
                  池子页签筛选，默认显示全部（永不空屏等用户选）
```

**不要做**：今日待办框、账户风险框（信息价值低，挤占核心区）。

### 7.3 标的详情页

```
英雄区    名称 + 方向徽章 + 状态胶囊 | 大字价格 + 涨跌 chip | 结构进度/回顾式总结
K线卡     满宽 480px+：日/周/月/1h/4h · 对数/线性 · 蜡烛/折线 · MA18/45/60/200/250 独立开关
          成交量副图 + MAVOL · 十字线显示 OHLC+涨跌幅+成交量
          画线工具条（左侧）· 全屏按钮（右上）
          图上元素：颈线蓝虚 / 目标红虚 / 回撤区橙色半透明横带 / 哨兵蓝点划 + ⚓
                    / 头部颈线红点划 / 历史信号旗标（共振入场、突破失败、结构衰竭…）
三列卡    结构与规则（各档价格+状态，按结构态分监控/回顾/休眠三种口径）
          关联指数（主副 + 各自完成度）
          质地（自动分环形 + 六维子分横条 + 数据时点）
操作卡    迁池 / 头部确认 / 期权备注 / 持仓录入
事件时间线 L1战役事件（默认显示）/ L2价位变更（按日聚合，显示净差异）/ L3操作流水（默认折叠）
回放页签  同页内切换
```

### 7.4 突破确立页

- **已共振**：主指数右侧、入场信号已出（半仓入场行内标注）
- **待共振**：个股已突破但主指数非右侧，写明在等什么
- 每行：突破日 | 突破价 | 现价涨跌 | 距突破位% | 完成度条 | 主指数状态 | 剧本收益 | 质地
- 移出条件：假突破 / 结构衰竭 / 头部确立 / 手动归档 → 页底「近期移出」保留 7 天

### 7.5 头部确立页

- **顶部观察中**：已画头部颈线且选"先观察"，显示头颈线价 / 现价 / 距颈线%
- **已确立**：确认日 / 确认时价格 / 当前价 / **确认后至今涨跌%** ← 看顶准确率档案
  - 准确率口径带 ±1% 中性带（否则确认当天必然显示 0% 被判"判早了"）
- 移出：满 90 天或该标的新一轮结构激活

### 7.6 账户页

持仓表（数量/成本/市值/盈亏）+ 现金/融资 + **模拟战役总账**（历史全轮次模拟收益逐轮列表与合计）。持仓支持手动录入与截图识别导入。

### 7.7 设置页

全部规则参数中文化分组展示，raw JSON 藏进"高级"；含运维区（手动采集/评估/推送、备份状态、最近备份时间）。

## 九、通知设计（飞书）

**每天一条**（收盘后），五档硬排序：

```
报头：各指数红绿灯 + 完成度  |  当日有 P1 事件时卡片头变红
档1 今日触发    清仓/假突破警报置顶，其后入场、减仓、回撤买回
档2 临门一脚    距触发位 ≤3%（含哨兵距离）
档3 逼近中      3~8%
档4 有变化      进度百分比变动明显的
档5 观察池其余  折叠一行汇总
财报动态节      当日新披露的业绩预告/快报
底部按钮        「打开看板」直达链接
```

每行用字符进度条（`▓▓▓▓▓░░░ 88%`）+ 距离 + 颜色标签；同档内按星标 → 质地排序。

**关键事件加推**（默认开）：突破/清仓级事件当天，紧随日报单独加推一条红头卡。

飞书自定义机器人安全设置建议用**自定义关键词**（比签名校验简单），关键词做成配置项并标注"不可删，删了飞书静默拒收"。

## 十、安全与运维

- **单用户鉴权，零打扰**：一次登录 cookie 365 天 + 带 token 的书签直达链接（打开自动登录并清除 URL 参数），密码框兜底
- 全部密钥走 `.env`（600 权限，进 .gitignore），部署 rsync 永久排除 `.env / secrets / evidence`
- **备份必须真实存在并验证**：每日 dump + WAL 归档 + 完整性自检 + 设置页显示"最近备份时间" + 定期演示一次真实恢复
- **API 日志落盘**：结构化访问日志 + 异常 traceback，保留 30 天，容器重建不丢；前端 5xx 报错显示错误编号供追溯
- 时区 Asia/Shanghai，交易日历用 Tushare
- 页面文档加 `no-store` 头（避免部署后仍跑旧 bundle 的假故障）
- 侧栏显示**构建时间戳**（一眼确认页面新旧）
