## 阶段 0 · 机制建设（最先做，别跳过）

```
项目启动前先建机制。仓库里创建两份文件：

1. docs/REQUIREMENTS.md 需求台账
   格式：编号 R-xxx | 描述 | 状态 | 验收标准 | 证据链接
   把 01-系统蓝图.md 与 02-交易方法论.md 里的所有功能点编号入册。

2. docs/REGRESSION.md 永久回归清单
   格式：编号 G-x | 测什么 | 怎么测 | 为什么在这里
   先按 03-AI协作工作流.md 第 1.2 节列出的 G-0~G-11 建立骨架。

此后每次交付前：台账逐条自测打勾、回归清单全跑，自查表随交付提交，
未全绿禁止请求验收。

工作方式（每轮遵守）：
1. 证据先行：任何"已验证/无法复现/正常"必须附可核对产物（截图/SQL输出/
   接口响应/测试日志原文/录屏），禁止叙述性结论
2. 线上取证：证据取自线上部署环境，禁止以本地构建充当
3. 沙箱隔离：一切测试写操作只作用于 TEST 沙箱标的
4. 禁止硬删：数据清理一律软删；涉及真实数据的删除必须先问我
5. 交易规则参数只能用 02 册指定值，禁止自行发明
6. 需求有歧义就停下来问，不要猜
7. 每完成一个模块自动 git commit
8. "检查/核实"类任务只做诊断，不做修改与删除

先确认这两份文件已建好并提交，再进入下一阶段。
```


## 阶段 3 · 数据层与规则引擎（核心）

```
实施数据层与规则引擎，这是系统的心脏，按 01 册第五、六节与 02 册执行。

一、数据层
1. 数据源可插拔 + 故障切换，路由按 01 册第五节表格
2. 全量历史回填：个股自上市日、指数自发布日；分年份/分页拉取 + 断点续跑 + 限频
3. 【必做】脏数据护栏：入库时坏收盘整行丢弃、坏 OHLC/量置 NULL；
   接口序列化对 NaN 兜底（历史深处的脏行会让全量历史接口崩 500，
   进而让周/月K切换静默失效 —— 这是真实踩过的坑）
4. 有效性闸门：解析结果 ≤0、为空、或偏离最近收盘 >20% 一律丢弃并保留上一有效值，
   界面标注"该源暂不可用"，绝不显示 0
5. 分市场交易时钟（含美股夏令时），只请求开市中的市场，休市显示"已收盘"

二、规则引擎
1. 引擎必须是纯函数：evaluate(instrument, trade_date, snapshot) → [Signal]，
   不依赖当前时间（这样历史回放天生可用）
2. 按 01 册 6.2 的评估顺序实现全部规则，参数全部读 settings
3. 去抖 key =（标的, 规则, 池子+子状态, 价位版本）
4. 方向标签压制闸门：标签为左侧/筑底时，规则层静默消费K线只推进日期，
   不产生任何信号；展示层抹掉完成度/距目标/剧本/模拟，换左侧语言
5. 历史回放功能：给定标的+年份逐日重演，输出事件序列
6. 【护栏】结构激活/峰值的扫描起点 = 价位版本生效日，与K线回填深度完全解耦

三、验收（必须做）
用一只真实标的的历史行情跑回放，人工核对每个触发日期与档位建议是否正确。
把事件序列表发我，我逐条核对。这是规则引擎唯一可信的验收方式。
```

## 阶段 4 · 前端（视觉与交互）

```
实施前端，按 01 册第七节的页面结构。

视觉规范（写死，不得偏离）：
- 主骨架参考 Copilot Money / Monarch Money：白底、圆角卡片、柔和阴影分层、
  彩色进度条为核心视觉元素、大量留白
- 图表与排版参考 Stripe Dashboard：克制精致、全站一个主色系
- 像素级规范：
  页面底色 #F7F8FA / 卡片 #FFFFFF / 圆角 16px / 边框 1px #EEF0F3
  阴影 0 1px 2px rgba(16,24,40,.04), 0 8px 24px rgba(16,24,40,.06)
  悬停 0 12px 32px rgba(16,24,40,.10) + 上浮2px / 200ms
  主色 #4F46E5；涨 #E23A3A 跌 #16A34A；警示 #F59E0B
  文字 #0F172A / #64748B / #94A3B8；数字 tabular-nums
  间距 8px 基数：卡片内边距24 / 卡片间距16 / 区块间距32
  动效：数字 count-up 300ms、页签 200ms、ease-out
- 禁止：玻璃拟态、3D透视、重渐变背景、两个以上主色、深色模式

结构性要求：
- 240px 左侧固定导航（不是顶部导航）；<1280px 收窄64px；移动端底部标签栏
- 全站满屏无居中窄栏
- 可视化密度硬规则：每张卡片至少一个图形元素，禁止纯文字卡

图表（KLineCharts，必须支持交互画线）：
- 周期：1时/4时/日K/周K/月K；坐标：对数/线性（默认对数）；图型：蜡烛/折线
- 均线 MA18/45/60/200/250 独立开关 + 顶部图例跟随十字线
- 成交量副图 + MAVOL5/10/20；十字线显示 OHLC+涨跌幅+成交量
- 全屏按钮（全屏内功能与非全屏完全一致）
- 画线工具：水平直线/水平射线/线段/斜射线/量度涨幅/删除
  两段式：画线先为草稿参考线（不弹窗不入库）→ 点选出浮动工具条
  （颜色8色块/线宽3档/实线虚线/删除/【确定】）→ 点确定才读价弹语义卡 → 确认写入
  工具条可拖动；点击工具条内部不关闭；只有点外部或 ESC 才关闭
  默认样式：红色 #E23A3A / 2px / 实线；用户改过后新线沿用最近选择（服务端持久化）
- 【几何铁律】确认写入只改变身份与样式，绝不改变几何：不截断、不缩短、不重画锚点
  水平线横贯全宽；射线锚定后延伸至图表右缘（含未来区）；线段严格两端为界
  图表右侧默认保留 30 根 K 线的未来空白区
- 【对数坐标】整线拖动必须是像素空间刚体平移（press/move/release 三段共用同一函数），
  对数下等价于两端点等比缩放；只验终点不算数，要验拖动过程每一帧
- 【命中检测】点到线段最短距离 12px；近垂直线段额外启用包围盒热区；
  端点手柄 14px 且优先级最高

自查循环：每轮改完自己截图 → 与参考图并排自评 → 列出 5 处最大差距 →
修掉 → 循环直到无重大差距 → 才允许提交。
```

```
实施通知闭环：

   关键词做成配置项并标注"不可删（删了飞书静默拒收）"
5. 手动触发一次真实推送作为验收

推送后把飞书收到的卡片截图发我。
```

## 阶段 6 · 缺陷报告模板（你日常使用）

发现问题时按这个格式发给 AI，能省它一半排查时间：

```
【缺陷】<一句话现象>

复现路径：<具体点了什么、在哪个页面、什么标的>
预期：<应该怎样>
实际：<实际怎样>
范围：<只有某个标的还是全部？某种线型还是全部？某个周期还是全部？>
截图/错误编号：<有就附上>

要求：
1. 先定根因再修，附 traceback 或定位过程
2. 修复标准：<明确的验收方式，涉及交互过程的要录屏>
3. 如果这是同一问题第二次出现，写明前一次为什么没修住，
   并把它升级为永久回归项
4. 沙箱标的执行验证，不碰真实数据
```

## 阶段 8 · 会话中断后的恢复

网络断连或上下文超限后，开新会话用这段接上：

```
接手 <项目路径> 项目。先读：
1. docs/REQUIREMENTS.md（需求台账）
2. docs/REGRESSION.md（回归清单）
3. git log 最近 10 条提交
4. 项目根目录的 01/02/05 三份规格文档

了解现状后，告诉我：
- 台账里哪些条目还没完成
- 最后一次提交做到哪一步
- 你判断的下一步

确认无误后继续。
```
