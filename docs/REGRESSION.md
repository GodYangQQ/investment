|---|---|---|---|
| **G-0** | **画线矩阵**：水平线/趋势线/纵向线 × {画/确认/取消} × 对数/线性 × 缩放后 | 详情页逐线型画一遍；每次刷新确认价位仍在；检查未确认不生效 | 原系统画线"修 A 坏 B"三次；线型漏测是主要返工源 |
| G-1 | 价位确认门槛：候选不参与评估，确认后才激活 | `python -m unittest tests.test_position_store` | 铁律②：任何绕过确认的写入都是缺陷 |
| G-2 | 对数坐标缩放/拖拽过程级不变形 | 缩放/拖动时每 100ms 采样两锚点价格比值（控制台脚本） | 原系统终点对、过程错，等比证明全绿但肉眼走样 |
| G-3 | 结构状态机：待突破/进行中/已兑现/已衰竭 + 回放起点护栏 | `python -m unittest tests.test_position_rules` | 状态机除法错误会直接改变减仓结论 |
| G-4 | 方向标签压制：左侧/筑底不产生入场、减仓、止盈 | 单测 `test_label_suppression` + 页面把标的改为左侧后跑规则 | 铁律①：人的判断必须压制自动判断 |

| G-6 | 阶梯减仓只提示新跨过的最高一档，不连发 | 单测 `test_ladder_and_final` | 一天跨 70/80/90 三档时连发三条，用户会误操作 |
| G-7 | 信号去抖：同标的同规则同状态只入库一次；改版重新武装 | 同一天连续 `POST /api/evaluate` 两次，信号数不增加；改价位版本后再跑 | 原系统每日重复推送，通知被无视 |
| G-8 | 哨兵 CRUD + 上限 2 条 + 距离分档 | 单测 + 页面添加第 3 条应报错；删除后重建 | 哨兵误挂真实指数是原系统真实事故 |
| G-9 | 禁硬删：核心表 DELETE 必须报错；标的删除只软删 | `tests/test_position_store.py::test_no_hard_delete` | 原系统 AI 硬删用户手画颈线且无备份（最严重事故） |
| G-10 | 幂等保存 + 铁律③：盘中数据不入引擎 | 同一天重复评估不重复记账；`grep` 规则模块无分钟/实时数据引用 | 盘中价进入规则会制造假信号 |
| G-11 | 沙箱标的 `TEST*` 不出现在列表/看板/统计/日报 | 建 `TEST001` 后刷新看板与日报，计数不变 | 测试写操作污染真实数据 |

| G-14 | 日报生成 + 飞书推送（配置 webhook 后） | `POST /api/report` 检查五段结构；`POST /api/push` 检查返回码 | 通知发不出去等于系统不存在 |
